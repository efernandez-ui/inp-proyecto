Quiero que implementes un sistema de filtros para un catálogo de productos (array `productos`).

Estructura de cada producto (ejemplo):
- tipo (string) => esto será la "Categoría"
- subtipo (string)
- brand (string)
- attrs (object) => atributos por producto (clave: valor)
- stock (object) con BUE/CUYO/NEA/NOA (números)
- precio / precioLista, img, titulo, codigo, etc.

REGLAS DE FILTRADO (jerarquía y comportamiento):

1) FILTRO PRINCIPAL: CATEGORÍA (tipo)
- El usuario puede seleccionar 0, 1 o múltiples categorías.
- El listado de productos se filtra por las categorías seleccionadas (si hay alguna).

2) SUBTIPOS y MARCAS DEPENDIENTES DE CATEGORÍA
- Cada vez que cambian las categorías seleccionadas, recalcula:
  a) Subtipos disponibles = subtipos únicos dentro de los productos resultantes (post-categoría).
  b) Marcas disponibles = brands únicas dentro de los productos resultantes (post-categoría).
- Los selectores de Subtipo y Marca deben mostrar SOLO opciones válidas para el conjunto actual (dependientes de la categoría filtrada).

3) FILTROS POR ATRIBUTOS (CONDICIONALES)
- Los filtros por atributos SOLO deben aparecer si y solo si:
  - hay EXACTAMENTE 1 categoría seleccionada.
- Si hay 0 categorías o hay 2+ categorías seleccionadas:
  - NO mostrar filtros por atributos (ocultarlos por completo),
  - pero SÍ mostrar Subtipos y Marcas dependientes (siempre).

4) CUANDO HAY 1 CATEGORÍA SELECCIONADA:
- Mostrar filtros por atributos basados en `attrs` de los productos visibles (luego de filtrar por categoría y también respetando si el usuario ya filtró por subtipo/marca).
- Regla: mostrar un atributo como filtro SOLO si:
  a) el atributo existe en al menos un producto visible
  b) y tiene al menos 2 valores distintos (si todos tienen el mismo valor, no mostrarlo)
- Los valores del filtro deben ser el conjunto de valores únicos (ordenados) para ese atributo.

5) FILTRO FINAL:
- El orden de aplicación debe ser:
  Categoría (tipo) -> Subtipo -> Marca -> Atributos -> (otros como precio/stock si existen)
- Cada cambio debe recalcular las opciones disponibles de:
  - Subtipos y Marcas según el set filtrado por Categoría
  - Atributos según el set filtrado por Categoría + Subtipo + Marca (solo si hay 1 categoría)

6) RESETEOS / CONSISTENCIA:
- Si el usuario cambia Categoría y algún Subtipo/Marca seleccionado deja de ser válido:
  - limpiar ese filtro automáticamente.
- Si el usuario pasa de 1 categoría seleccionada a 2+:
  - borrar selecciones de atributos y ocultarlos.
- Si vuelve a 1 categoría:
  - reconstruir el panel de atributos desde cero.

IMPLEMENTACIÓN:
- Crear funciones puras:
  - filterProducts(products, state) -> prod
